BMI Tracker – ระบบบันทึกดัชนีมวลกายและแสดงผลการวัดสุขภาพเบื้องต้น

1. แนวคิดหลักของการออกแบบ (Design Philosophy)

การออกแบบ UI/UX ของโปรเจกต์นี้ยึดจากหลักการ:

🔹 Human-Centered Design (HCD)

คือออกแบบตามพฤติกรรมผู้ใช้จริง
เป้าหมาย: ให้ผู้ใช้ใช้งานได้ทันทีโดยไม่ต้องคิดมาก

🔹 Cognitive Load Theory

ลดภาระความคิด (mental effort)
→ จัดองค์ประกอบตามความสำคัญ
→ ลดจำนวนปุ่ม
→ ให้ feedback ทันที

สรุป: UI ต้อง “ชัดเจน → ง่าย → ใช้ได้ทันที”

2. การจัดวางองค์ประกอบหลักของหน้า (UI Layout Decisions)
2.1 วางฟอร์มกรอกข้อมูลด้านบน

ใส่น้ำหนักและส่วนสูงเป็นจุดเริ่มต้นของระบบ
เป็น “primary action” ของผู้ใช้
มองเห็นชัดเจนโดยไม่ต้องเลื่อนหน้า

เหตุผล

ลดความสับสนของผู้ใช้ใหม่
ทำให้รู้ทันทีว่า “ต้องเริ่มตรงไหน”
ลด Cognitive Load

2.2 ปุ่มเดียว: “Calculate & Save”

แทนการแยกเป็น 2 ปุ่ม (คำนวณ + บันทึก)

เหตุผล
เวิร์กโฟลว์ง่าย: 1 action = 1 การทำงาน
ประสบการณ์ใกล้เคียงเครื่องมือจริง (เครื่องชั่ง → แสดงผลทันที)
ลดความผิดพลาด และ job-to-be-done ชัดเจน
กดครั้งเดียว → คำนวณ BMI + บันทึกประวัติ

2.3 แสดงผล BMI ใต้ฟอร์มทันที

แสดง BMI (ตัวเลข)
แสดงหมวดหมู่สุขภาพ
แสดงวันที่/เวลา

เหตุผล

Immediate feedback → UX ดีมาก

ผู้ใช้ไม่ต้องตีความเอง
ไม่จำเป็นต้องเลื่อนลง
หลักจิตวิทยา UI

ผู้ใช้ต้องการผลลัพธ์ทันทีเพื่อยืนยันว่าการ input ถูกต้อง

3. การนำเสนอข้อมูลในส่วนประวัติ (Historical Data)
3.1 ตารางประวัติ (History Table)

ใช้แสดงข้อมูลแบบละเอียด ได้แก่:
วันที่/เวลา
น้ำหนัก
ส่วนสูง
BMI
หมวดสุขภาพ
ปุ่มลบ (ลบ record ที่ผิด)

เหมาะสำหรับ :
การตรวจสอบ
การเปรียบเทียบตัวเลข
การแก้เฉพาะ record
ตารางตอบโจทย์ “การอ่านแบบ Data”

3.2 กราฟเส้น (Line Chart)

ใช้เพื่อแสดงแนวโน้ม (Trend) ของค่า BMI ตามเวลา

เหตุผล
มนุษย์เข้าใจภาพรวมจากเส้นได้ดีกว่าตัวเลข
เห็นความเปลี่ยนแปลงแบบระยะยาว
สื่อสารการขึ้น–ลงได้ชัดเจน
กราฟตอบโจทย์ “การอ่านแบบภาพรวม”

4. การใช้สีเพื่อสื่อสถานะสุขภาพ (Color Strategy)
หมวดหมู่	สี	เหตุผล UX
ผอม	น้ำเงินอ่อน	ไม่สร้างแรงกดดัน
ปกติ	เขียว	สื่อความปลอดภัย / สุขภาพดี
น้ำหนักเกิน	เหลือง–ส้ม	สื่อเตือน → ยังไม่อันตราย
อ้วน	แดง	สื่ออันตราย → ควรปรับพฤติกรรม

เหตุผลสำคัญ
สมองรับรู้ “สี” เร็วกว่าตัวหนังสือ
ผู้ใช้ “เห็นแล้วเข้าใจ” โดยไม่ต้องอ่านคำอธิบายยาว
สี = ภาษาแบบสากล (Universal language)

5. Interaction Design (การโต้ตอบของผู้ใช้)
5.1 การลบข้อมูล
ปุ่มลบแต่ละแถว
ไม่ต้อง confirm หลายขั้นตอน
ลด friction

5.2 การบันทึกอัตโนมัติ

ระบบบันทึกข้อมูลลง localStorage เมื่อคำนวณทันที
ไม่ต้องแยกปุ่ม Save

5.3 ไม่มี Login/Signup

ลดขวาก UX
เหมาะกับ Single User
เหมาะกับ prototype/MVP

6. Persistence (การเก็บข้อมูล)

เลือกใช้ LocalStorage เนื่องจาก:
ไม่ต้องติดตั้ง Database ภายนอก
ใช้งานได้ทันทีใน Browser
ไม่มีการเชื่อมต่ออินเทอร์เน็ต
ง่ายต่อการพัฒนา front-end
เลือกเพื่อความเรียบง่ายและความเร็ว (MVP Principle)

7. ความสม่ำเสมอ (Consistency)

ใช้โครง heading: H1 > H2 > H3
ขนาด Text สม่ำเสมอ
ฟอร์ม/ปุ่มมีรูปแบบเดียวกัน
<hr/> ใช้แบ่ง section ให้ชัดเจน

Layout จากบนลงล่าง:
Input → Current Result → History → Graph
ทำให้ผู้ใช้เข้าใจ flow ตามธรรมชาติ

8. Accessibility

Contrast ข้อความ/พื้นหลังอ่านง่าย
ตารางช่วยจัดข้อมูลให้ชัดเจน
ไม่ใช้สีเพียงอย่างเดียว: มีข้อความข้างเคียง
องค์ประกอบไม่แน่นเกินไป

9. เหตุผลสรุปที่ทำให้ Design นี้ “เวิร์ค”

✔ ลด Cognitive Load
✔ ใช้งานได้ทันที
✔ ให้ Feedback แบบ Real-time
✔ รองรับทั้ง Data view และ Trend view
✔ ใช้สีช่วยสื่อสารโดยไม่ต้องอธิบาย
✔ โครงสร้าง UI ตรงตาม Natural Interaction ของผู้ใช้

🟢 Conclusion

BMI Tracker ถูกออกแบบให้ใช้งานง่าย มีประสิทธิภาพ และสนับสนุนการตัดสินใจด้านสุขภาพของผู้ใช้

ผู้ใช้:

1.เริ่มใช้งานทันที
2.เข้าใจผลลัพธ์ทันที
3.ติดตามข้อมูลระยะยาว
4.ไม่ต้องมีพื้นฐานเทคนิค
