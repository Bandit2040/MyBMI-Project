 Technology Stack Justification – BMI Tracker

## 1. Programming Language

**JavaScript (พร้อม HTML และ CSS)**  
ระบบนี้ถูกพัฒนาบนพื้นฐานของภาษา JavaScript ร่วมกับ HTML/CSS เนื่องจากเป็นเทคโนโลยีหลักสำหรับการพัฒนา Web Application ที่ทำงานบน Browser ผู้ใช้สามารถใช้งานระบบได้ทันทีผ่านเว็บ โดยไม่ต้องติดตั้งโปรแกรมเพิ่มเติม เหมาะกับขอบเขตของโปรเจกต์ที่ต้องการ UI แบบโต้ตอบและตอบสนองแบบ Real-time

เหตุผลที่เลือก:
- เป็นภาษาที่รองรับโดย Browser ทุกตัว
- ทำงานร่วมกับ React.js ได้ดี
- เหมาะกับโปรเจกต์ขนาดเล็ก–กลาง ที่เน้นการโต้ตอบกับผู้ใช้ (Interactive UI)

---

## 2. Frontend Framework

**React.js**

React.js ถูกเลือกใช้สำหรับพัฒนา User Interface ของระบบ BMI Tracker เนื่องจากเป็น JavaScript library ที่ออกแบบมาสำหรับสร้าง Single Page Application (SPA) ที่มีการเปลี่ยนแปลงสถานะของข้อมูลบ่อยครั้ง เช่น การคำนวณ BMI และการอัปเดตรายการประวัติอย่างต่อเนื่อง

เหตุผลที่เลือก:
- ทำให้การจัดการ State (เช่น ข้อมูล BMI และประวัติการบันทึก) เป็นระบบและเข้าใจง่าย
- แบ่งส่วนหน้าจอเป็น Component ย่อย ทำให้โค้ดอ่านง่ายและบำรุงรักษาง่าย
- รองรับการอัปเดต UI แบบ Real-time โดยไม่ต้องโหลดหน้าเว็บใหม่
- เหมาะกับโจทย์ที่ต้องการ Interaction และการแสดงกราฟ/ตารางแบบ Dynamic

---

## 3. Backend (Server-side)

**Node.js + Express.js** *(ถ้าใช้)*

หากต้องการให้ระบบสามารถเก็บข้อมูลบน Server หรือรองรับการขยายระบบในอนาคต จึงเลือกใช้ Node.js ร่วมกับ Express.js ในการพัฒนา REST API สำหรับรับ–ส่งข้อมูลระหว่าง Frontend และ Server

เหตุผลที่เลือก:
- ใช้ภาษา JavaScript ทั้งฝั่ง Frontend และ Backend ทำให้การพัฒนาเป็นไปในทิศทางเดียวกัน (JavaScript ทั้ง stack)
- Node.js รองรับ I/O ที่รวดเร็ว เหมาะกับ Web Service ขนาดเล็ก–กลาง
- Express.js มีโครงสร้างที่เรียบง่าย เหมาะกับโปรเจกต์วิชาการที่ต้องการแสดงความเข้าใจเรื่อง Client–Server Architecture

> หมายเหตุ: หากรอบนี้เน้นความง่ายเป็นหลัก ระบบสามารถทำงานได้โดยใช้เฉพาะ React.js + localStorage โดยไม่จำเป็นต้องมี Backend จริงก็ได้

---

## 4. Data Storage

**LocalStorage (Browser Storage)**

สำหรับโปรเจกต์นี้ เลือกใช้ `localStorage` ใน Browser เพื่อเก็บประวัติ BMI (วันที่, น้ำหนัก, ส่วนสูง, ค่า BMI, หมวดหมู่) เนื่องจากระบบถูกออกแบบมาสำหรับผู้ใช้คนเดียวต่อเครื่อง และไม่มีความจำเป็นต้องแชร์ข้อมูลผ่านหลายอุปกรณ์

เหตุผลที่เลือก:
- ใช้งานง่าย ไม่ต้องตั้งค่า Database Server เพิ่มเติม
- เพียงพอกับขอบเขตของระบบที่ต้องการแค่การบันทึกและเรียกดูประวัติบนเครื่องของผู้ใช้
- ช่วยลดความซับซ้อนของระบบในระดับ Final Project แต่ยังแสดงให้เห็นแนวคิด Data Persistence ได้

*(ถ้าต้องการต่อยอดในอนาคต สามารถเปลี่ยนไปใช้ Database จริง เช่น SQLite หรือ MongoDB ได้โดยไม่กระทบกับการออกแบบหน้าบ้านมากนัก)*

---

## 5. Library เพิ่มเติม

**Chart.js** *(หรือ Library กราฟอื่น)*

เลือกใช้ Chart.js สำหรับวาดกราฟเส้นแสดงค่า BMI ตามเวลา เนื่องจาก:
- ใช้งานง่ายและมีตัวอย่างโค้ดให้ศึกษา
- รองรับการแสดงผลกราฟแบบ Line Chart ได้ดี
- ช่วยให้สามารถทำ Basic Reporting ตามโจทย์ที่กำหนดไว้ได้อย่างรวดเร็ว

---

## 6. สรุปความเหมาะสมกับโจทย์

ชุดเทคโนโลยี React.js + JavaScript + (Node.js/Express.js) + LocalStorage/Chart.js เหมาะสมกับโจทย์ BMI Tracker เนื่องจาก:
- รองรับการคำนวณและอัปเดตข้อมูลแบบ Real-time
- แสดงประวัติและกราฟได้อย่างโต้ตอบ (Interactive)
- มีโครงสร้างที่ชัดเจน สามารถอธิบายในเชิงสถาปัตยกรรมซอฟต์แวร์, SDLC และ System Design ได้
- ไม่ซับซ้อนเกินไปสำหรับขอบเขตของ Final Project แต่ยังดูเป็นงานในระดับวิศวกรรมซอฟต์แวร์จริง
